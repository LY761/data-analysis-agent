# 电商自动化模块全景与 Web 展示规划

> 目标：让市面上常见的电商分析与自动化能力在项目中都有清晰入口和可演示结果；核心经营分析做成真实闭环，依赖商业平台权限的动作保留连接器和审批接口。

## 1. 市场能力基线

本项目的自动化模块地图参考以下官方产品能力：

- [Shopify Flow](https://help.shopify.com/en/manual/shopify-flow/reference) 使用触发器、条件、动作和连接器组织自动化，覆盖订单、客户、库存、履约、促销和风险等场景。
- [Shopify Analytics](https://help.shopify.com/en/manual/reports-and-analytics/shopify-reports) 以可定制经营看板、指标卡、报告和数据探索承载经营分析。
- [Klaviyo Flows](https://help.klaviyo.com/hc/en-us/articles/115002774932) 的典型生命周期流程包括欢迎、弃购、购后和召回。
- [Gorgias Rules](https://docs.gorgias.com/en-US/create-rules-to-take-automatic-actions-on-tickets-81746) 使用事件、条件和动作完成工单标签、自动回复、分配和关闭。
- [Adobe Commerce Merchandising](https://experienceleague.adobe.com/en/docs/commerce/optimizer/merchandising/overview) 将搜索、类目规则、商品推荐和个性化用于商品运营。

因此项目不应只做“问数聊天框”，而应同时具备经营分析、场景自动化和统一工作流三个产品层。

## 2. 自动化成熟度

所有模块使用同一套成熟度，避免页面存在就被误认为已经具备生产自动化：

| 等级 | 含义 | Web 表现 | 当前目标 |
|---|---|---|---|
| L0 展示 | 能看到模块、说明、示例数据和所需数据源 | 模块卡片、示例结果、连接状态 | 所有模块 |
| L1 分析 | 能基于上传或数据库数据生成确定性指标和结论 | 看板、诊断、证据、报告 | 核心经营模块 |
| L2 辅助自动化 | 能生成任务、策略或动作草稿，由用户确认 | 待办、审批、模拟影响、手动执行 | 运营动作模块 |
| L3 自动执行 | 能通过平台连接器真正改变外部业务状态 | 执行记录、回滚、审计 | 当前只保留接口 |

Web 首期要求所有模块达到 L0，经营分析模块达到 L1，低风险站内任务达到 L2；任何外部改价、退款、调预算、改库存和触达动作都不默认进入 L3。

## 3. 三种运行形态

项目不采用“所有模块都是 Agent”的设计。每个能力按问题性质选择确定性服务、简单工作流或 Agent，复杂场景可以组合，但必须保持职责边界。

### 3.1 确定性服务

适用于输入、公式和输出可明确描述的能力：

- 指标计算、同比环比、漏斗和利润拆解。
- 数据映射、质量检查、去重和快照。
- SQL 校验、权限、脱敏、导出和图表规格。
- 异常规则、评分、预测、补货量和关联购买算法。
- 仪表盘查询、报告数据集和接口契约。

要求：相同输入得到相同输出；核心数值不得交给 LLM 计算。

### 3.2 简单工作流

适用于步骤固定、条件清晰、需要调度或状态管理的能力：

- 定时日报、周报和月报。
- 销售下降、低库存、履约超时和高退款率告警。
- 欢迎、弃购、购后、复购和召回流程。
- 创建任务、分配负责人、审批、通知、重试和回滚。
- 数据同步、质量校验、快照生成和刷新失败处理。

统一模型：`Trigger → Condition → Service/Agent → Approval → Action → Result`。

### 3.3 Agent

只用于输入模糊、需要理解上下文、动态选择工具或处理非结构化信息的能力：

- 自然语言问数、追问和多轮澄清。
- 跨指标根因分析与开放式经营诊断。
- 竞品、选品和市场资料综合研究。
- 活动方案、商品策略和运营建议草拟。
- 客服多轮对话、知识检索和人工转接判断。

Agent 输出结论或动作草稿；指标服务提供事实；工作流控制执行。Agent 不直接改价、退款、调预算、改库存或发送大规模营销消息。

### 3.4 选择规则

| 判断问题 | 选择 |
|---|---|
| 能否用公式、SQL 或规则完整表达？ | 确定性服务 |
| 步骤是否固定，只是等待事件、判断条件和执行动作？ | 简单工作流 |
| 是否需要理解自然语言、非结构化资料或动态选择多个工具？ | Agent |
| 是否既有固定步骤又有开放式分析？ | 工作流编排服务和 Agent，Agent 仅占其中一个节点 |
| 是否产生外部副作用？ | 必须经过工作流、权限和审批，不能由 Agent 直接执行 |

## 4. 一级模块总览

| 一级模块 | 默认运行形态 | Agent 使用点 | 当前覆盖 | Web 首期目标 |
|---|---|---|---|---|
| 经营驾驶舱 | 确定性服务 | 异常摘要和追问 | 部分 | L1 |
| 智能问数 | Agent + 确定性 SQL 工具 | 意图理解、澄清、工具选择 | 已有 | L1 |
| 商品运营 | 确定性服务 + 工作流 | 开放式商品诊断和建议 | 部分 | L1/L2 |
| 流量与转化 | 确定性服务 | 跨维度根因总结 | 缺失 | L1 |
| 广告投放 | 确定性服务 + 工作流 | 素材理解和策略草稿 | 缺失 | L0/L1 |
| 用户与会员 | 确定性服务 | 分群解释和策略草稿 | 少量 | L1 |
| 营销自动化 | 简单工作流 | 内容草稿和复杂分群解释 | 缺失 | L0/L2 |
| 订单与履约 | 简单工作流 + 规则服务 | 特殊案例辅助判断 | 少量 | L0/L1 |
| 库存与供应链 | 确定性服务 + 工作流 | 例外情况解释 | 部分 | L1/L2 |
| 售后与口碑 | 确定性服务 + 工作流 | 文本主题、归因和客服对话 | 部分 | L1/L2 |
| 市场与竞争 | Agent + 数据采集服务 | 多来源研究和选品推理 | 部分 | L1 |
| 商品推荐与陈列 | 确定性算法服务 | 文案和策略解释 | 缺失 | L0/L1 |
| 报告与预警 | 简单工作流 + 报告服务 | 管理层摘要 | 部分 | L1/L2 |
| 自动化中心 | 简单工作流引擎 | 仅作为可选分析节点 | 缺失 | L1/L2 |
| 数据与治理 | 确定性服务 + 数据工作流 | 字段映射建议 | 部分 | L1 |

## 5. 经营驾驶舱

### 5.1 功能

- 今日、本周、本月 GMV、订单、销量、买家数和客单价。
- 流量、支付转化率、退款率、毛利率、ROAS 和库存健康度。
- 同比、环比、目标完成率和预测落点。
- 指标异常、原因摘要、影响金额和待处理任务。
- 按店铺、平台、渠道、类目、商品和时间筛选。

### 5.2 当前差距

- 已有快捷卡片、BI 异常和确定性店铺指标，但没有统一首页。
- 指标来自不同服务，口径和过滤条件可能不一致。
- 缺少目标值、预测值、影响金额和异常处置状态。

### 5.3 首期展示

- 8 个核心指标卡。
- 经营趋势图和流量转化漏斗。
- 异常榜、商品风险榜和自动化待办。
- 每张卡支持下钻到证据和对应场景。

## 6. 商品运营自动化

### 6.1 功能

- SPU/SKU 销量、GMV、利润、转化、退款、评分和库存综合健康度。
- 新品冷启动、潜力品、引流品、利润品、滞销品和风险品标签。
- 商品对比、价格带分析、关联购买和组合销售建议。
- 标题、卖点、属性完整度和详情页问题检查。
- 上下架、促销、补货、清仓和内容优化建议。

### 6.2 当前状态与改造

- 复用已有商品对比、低评分商品、评论痛点和市场商品研究。
- 增加统一商品画像和 SKU 粒度，取消固定权重评分。
- 自动动作首期只生成运营任务，不直接改价或上下架。

## 7. 流量与转化自动化

### 7.1 功能

- 展现 → 点击 → 访问 → 加购 → 下单 → 支付漏斗。
- 渠道、设备、页面、地区、新老客和商品维度拆解。
- 异常流量、低点击、高跳失、低加购和低支付转化识别。
- GMV 变化自动拆解为流量、转化率和客单价贡献。
- 落地页、价格、库存、评价和人群匹配问题建议。

### 7.2 当前差距

当前数据库偏订单结果数据，缺少曝光、点击、访问、加购和支付买家等过程事实表。这是从通用分析 Agent 升级为电商运营 Agent 的最大数据缺口之一。

## 8. 广告投放自动化

### 8.1 功能

- 计划、单元、关键词、人群、素材和商品层级看板。
- 曝光、点击、CTR、CPC、CPM、转化率、成交额和 ROAS。
- 低效计划、烧钱关键词、素材衰退和预算受限识别。
- 预算增减、暂停、否词、换素材和调人群建议。
- 投放前后增量、自然流量挤压和利润约束分析。

### 8.2 首期边界

- 提供标准广告数据模板和粘贴数据分析。
- 使用规则和利润约束生成预算建议及模拟结果。
- 不直接调用平台调整预算，保留 `AdActionConnector`。

## 9. 用户与会员自动化

### 9.1 功能

- RFM 分群、新客、复购客、VIP、沉睡、流失风险和高潜人群。
- 首购周期、复购周期、购买频次、客单、累计价值和预测 LTV。
- 品类偏好、价格偏好、优惠敏感和渠道偏好。
- 人群规模、收入贡献、留存、复购和迁移趋势。
- 分群导出和营销流程受众预览。

### 9.2 当前状态与改造

- 已有会员分析快捷查询，但不足以形成生命周期管理。
- 新增客户事实表、RFM 结果快照、分群规则和人群版本。
- 隐私同意、退订和触达频控必须成为分群过滤条件。

## 10. 营销自动化

### 10.1 模板

- 欢迎流程：新订阅或新会员进入后分阶段触达。
- 浏览未购：浏览商品但未加购或未购买。
- 加购/结账放弃：进入购物车或结账但未支付。
- 购后流程：物流提醒、使用指南、评价邀请和关联推荐。
- 复购提醒：按商品消耗周期或历史复购周期触发。
- 召回流程：沉睡客户、流失风险和历史 VIP 召回。
- 生日、会员升级、积分到期、优惠券到期提醒。
- 降价、补货、到货和收藏商品变化提醒。

### 10.2 首期展示

- 展示流程模板、预估受众、触发条件、步骤和预期指标。
- 生成邮件、短信或站内消息草稿。
- 支持模拟运行与用户确认，不连接真实消息平台。

## 11. 订单、履约与风险自动化

### 11.1 功能

- 大额、重复、地址异常、高退款风险和疑似欺诈订单识别。
- 未支付、超时未发货、物流停滞、签收异常和取消订单监控。
- 订单标签、优先级、仓库路由和人工复核任务。
- 履约时效、物流商表现、取消原因和赔付分析。

### 11.2 首期边界

- 分析、告警、打站内标签和创建任务可自动完成。
- 支付捕获、取消、退款和改地址必须经过审批且需要平台连接器。

## 12. 库存与供应链自动化

### 12.1 功能

- 低库存、缺货、超卖、滞销、库龄和库存资金占用。
- 销速、可售天数、安全库存、补货点和建议补货量。
- 在途、采购周期、供应商交期和季节性修正。
- 仓间调拨、采购、促销清仓和停售建议。

### 12.2 当前状态与改造

- 已有低库存告警和动销率，但没有库存快照、在途和补货周期。
- 首期用历史销量和当前库存生成补货任务草稿。
- 自动采购、调拨和库存修改只保留 `InventoryActionConnector`。

## 13. 售后、评价与客服自动化

### 13.1 功能

- 退款率、退款金额、原因、责任和商品/SKU 归因。
- 评价情感、主题聚类、问题趋势、版本或批次问题定位。
- 咨询和工单自动分类、标签、优先级、路由、回复草稿和 SLA。
- 高频问题进入知识库候选，产品问题进入商品改进任务。
- 售前咨询、售后问题和经营数据联动。

### 13.2 项目分工

- `data-analysis-agent` 负责评价、退款、问题趋势和经营影响分析。
- `customer-service-agent` 负责会话、工单、回复、人工接管和渠道适配。
- 两者通过已有 REST/MCP 能力边界协作，不复制客服业务代码。

## 14. 市场、竞品与选品自动化

### 14.1 功能

- 类目规模、增速、价格带、品牌集中度和季节性。
- 竞品价格、销量、评分、评价、促销和卖点变化快照。
- 用户痛点、未满足需求、差评主题和机会词。
- 选品评分、利润测算、竞争强度、风险和数据可信度。
- 竞品变化、价格变化和新品出现的监控任务。

### 14.2 首期边界

- 优先使用用户上传、授权 API 或企业数据库。
- 公网搜索和抓取只作为可选插件，必须显示来源、采集时间和覆盖率。
- 不输出无法由证据支持的“爆款概率”或“蓝海指数”。

## 15. 商品推荐、搜索与陈列

### 15.1 功能

- 热销、相似商品、看了又看、买了又买、搭配购和复购推荐。
- 搜索词零结果、低点击词、同义词、类目规则和商品置顶建议。
- 交叉销售、向上销售、个性化推荐位和推荐效果分析。

### 15.2 首期展示

- 基于订单明细生成关联购买规则。
- 展示推荐商品、支持度、置信度、预估覆盖和原因。
- 不直接发布到店铺前台，保留 `MerchandisingConnector`。

## 16. 活动与促销自动化

### 16.1 功能

- 活动前选品、人群、价格、库存和利润模拟。
- 活动中 GMV、转化、库存、广告和异常实时监控。
- 活动后增量收入、利润、拉新、复购和渠道归因。
- 大额折扣、叠加优惠、毛利跌破阈值和库存不足预警。

### 16.2 首期边界

- 支持活动方案模拟、风险检查和复盘报告。
- 优惠券创建、改价和发布必须审批并通过平台连接器执行。

## 17. 报告、预警与任务中心

### 17.1 功能

- 日报、周报、月报、活动报告和专项诊断报告。
- 指标越界、趋势变化、数据中断和自动化失败告警。
- 待办任务、负责人、截止时间、状态、处理记录和效果复盘。
- 站内通知优先，外部通知通过保留的 `NotificationSink` 扩展。

### 17.2 统一闭环

`发现异常 → 生成证据 → 创建建议 → 转为任务 → 人工确认 → 记录结果 → 复盘影响`

## 18. 自动化中心

### 18.1 工作流模型

统一使用：

`Trigger（触发器） → Condition（条件） → Analysis（分析） → Action（动作） → Approval（审批） → Result（结果）`

### 18.2 首期触发器

- 定时：每日、每周、每月或自定义周期。
- 数据事件：数据刷新完成、订单导入、库存变化、评价新增。
- 指标事件：越过阈值、连续变化、异常分数触发。
- 手动：单条或批量运行。

### 18.3 首期动作

- 生成报告。
- 创建站内告警或任务。
- 生成运营建议和消息草稿。
- 调用内部分析工具。
- 发送 Webhook 测试请求。
- 商业平台动作显示为“连接器未启用”，不静默假执行。

### 18.4 运行治理

- 草稿、启用、停用和版本历史。
- 幂等键、重试、超时、失败原因和重跑。
- 模拟运行、影响范围预览和测试数据。
- 审批人、执行人、执行前后状态和回滚信息。

## 19. 动作风险分级

| 等级 | 动作 | 默认策略 |
|---|---|---|
| A 只读 | 查询、分析、报告、预测、建议 | 可自动运行 |
| B 站内 | 创建任务、站内标签、站内通知 | 可配置自动运行 |
| C 外部触达 | 邮件、短信、客服回复、群通知 | 需要开关、频控、同意状态和审计 |
| D 业务变更 | 改价、上下架、改库存、调预算、取消订单 | 必须审批、权限校验和可回滚 |
| E 财务/售后 | 退款、支付捕获、赔付、自动采购 | 默认禁用，必须强审批和平台授权 |

## 21. 实施策略

### 第一批：真实可用

- 经营驾驶舱、智能问数、商品运营、流量转化、库存、售后、报告。
- 指标语义层、数据映射、诊断引擎、证据链和任务中心。
- 自动化中心先支持定时、指标触发、生成报告和创建站内任务。

### 第二批：可演示可辅助

- 广告、用户会员、营销流程、活动、推荐、订单风险和市场监控。
- 使用上传模板和示例数据完成 L0/L1 演示。
- 外部动作只生成草稿、模拟和审批任务。

### 第三批：按客户启用

- 钉钉、飞书、企微、微信、淘宝、京东等真实连接器。
- 外部触达、改价、库存、投放、订单和退款动作。
- 多租户权限、审计、审批、队列、重试和回滚。

## 22. 完成判定

1. 17 个 Web 模块都有入口、说明、状态和演示结果。
2. 模块清晰标识 L0/L1/L2/L3，不把演示能力冒充生产能力。
3. 核心指标跨驾驶舱、诊断、问数和报告结果一致。
4. 至少能配置并运行“定时日报”“销售下降告警”“低库存任务”三条自动化。
5. 自动化运行有日志、输入快照、输出、状态、耗时和错误信息。
6. 高风险动作默认禁用，并明确显示所需连接器、权限和审批。
7. 新模块通过注册表接入，不继续向巨型路由和巨型工作流堆条件分支。
