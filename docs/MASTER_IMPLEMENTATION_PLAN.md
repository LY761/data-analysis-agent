# 电商数据分析 Agent 总体实施规划

## 1. 项目目标

将项目建设为可写入 Agent 应用开发简历的企业级作品：能够解释为什么某些场景使用 Agent，为什么另一些场景使用确定性服务或固定工作流，并展示安全、权限、工具调用、兜底、评测和企业接入能力。

## 2. 当前范围

### 保留并持续改造

1. 智能问数 Agent。
2. Schema 混合检索与关系图。
3. 指标语义层和电商标准模型。
4. 数据接入、质量检查、标准化和快照。
5. 店铺与商品诊断。
6. 经营驾驶舱和版本化报告。
7. 自动化工作流、任务和运行记录。
8. 权限、脱敏、缓存、审计、观测和评测。
9. Web、REST 和 MCP 接入边界。

### 不进入主项目

1. 企业知识库 RAG。
2. 通用联网搜索。
3. 京东/Amazon 爬虫和登录会话。
4. 竞品、选品和市场情报。
5. 旧 BI、旧报告兼容接口和重复通信入口。

## 3. Agent / 服务 / 工作流边界

| 场景 | 类型 | 原因 |
|---|---|---|
| 自然语言问数 | Agent | 输入表达开放，需要理解、澄清和工具选择 |
| Schema 选择与 SQL 生成 | Agent 工具链 | 存在语义映射与组合推理 |
| 指标计算 | 领域服务 | 公式固定，必须稳定可审计 |
| 数据质量与标准化 | 领域服务 | 规则明确，结果需可复现 |
| 店铺/商品风险分级 | 领域服务 | 阈值和证据必须确定 |
| 日报、异常扫描、低库存任务 | 工作流 | 步骤固定，需要状态、重试和幂等 |
| 对外通知草稿 | 可选 Agent | 文案开放，但发送动作必须走审批工作流 |
| 图表推荐 | 规则 | 数据形态可直接决策，无需模型 |

## 4. 已完成整改

### 范围收敛

- 删除 RAG、联网搜索、爬虫、竞品、选品和市场情报代码。
- 删除其专属 API、MCP 工具、能力注册、前端入口、配置和测试。
- 删除旧 BI、自动分析和旧报告兼容接口。
- 保留新报告、看板、诊断、语义层、自动化和企业接入。

### P0 安全与正确性

- 修复认证公共路径 `/` 导致全部 API 被前缀放行的问题。
- 将表权限接入 SQL Validator。
- 修复脱敏依赖 `success` 字段导致 API 结果不脱敏的问题。
- 调整为脱敏后写缓存。
- 扩展缓存隔离维度到租户、用户、权限、数据源、Schema、模型和 Prompt 版本。
- 使用 SQLite progress handler 实现真实查询截止时间。
- 修复 Langfuse 永不初始化的问题并增加 Trace 脱敏。
- 生产环境关键安全配置缺失时拒绝启动。

### 性能与 Token

- 问候、帮助和指标定义走 0 Token 快路径。
- 高频查询走预写 SQL。
- 明确数据问题跳过 LLM 路由。
- SQL 生成同时返回解释，避免额外回译调用。
- SQL 修复最多一次。
- 默认使用规则结果摘要，LLM 润色改为显式开关。

### Schema 检索

- 高置信精确关键词直接返回。
- 其他请求融合关键词和向量召回。
- 向量故障时关键词兜底。
- 关系图自动补齐桥接表和 JOIN 路径。
- 输出表、字段、关系、指标、维度、JOIN 路径、样例、证据和检索元数据。
- 低置信结果先澄清，不冒险生成 SQL。

## 5. 后续实施阶段

### Phase 1：统一 API 契约

- 建立 `ApiResponse[T]`、`ApiError`、`ResponseMeta`。
- 统一 HTTP 状态码、错误码、`trace_id` 和 `request_id`。
- 统一 SSE 事件：`status`、`tool_call`、`tool_result`、`answer`、`error`、`done`。
- 为核心接口补齐 `response_model`。

验收：核心接口不再混用 `error`、`detail`、`message`，失败不返回 HTTP 200。

### Phase 2：LLM Gateway

- 集中模型客户端、超时、重试、熔断和 Token 统计。
- 按任务配置模型与预算：router、clarify、sql_generate、sql_repair、analysis、report。
- 统一 JSON Schema 校验和解析失败重试。
- 记录每类任务 P50/P95 延迟、Token 和失败率。

验收：业务模块不再直接创建 `OpenAI` 客户端。

### Phase 3：租户与数据源隔离

- 租户从认证上下文获取，不接受调用方任意覆盖。
- 数据源改为请求级绑定，删除全局 `_current_db` 和全局执行器切换。
- Schema 索引、缓存、报告、快照和工作流记录全部带租户与数据源版本。
- 数据库账户生产环境强制只读。

验收：并发用户切换数据源互不影响，越权表查询被拒绝并有审计记录。

### Phase 4：工具与审计标准

- 建立 `ToolDefinition`、`ToolCallRecord` 和工具注册表。
- 工具声明输入输出 Schema、风险等级、超时、幂等键和权限。
- 外部消息、写操作和高风险动作进入审批工作流。
- Trace 关联路由、检索、SQL、工具调用、缓存和最终响应。

验收：每次 Agent 决策和工具调用都能按 `trace_id` 回放。

### Phase 5：可靠性与评测

- 扩充 Golden Case：路由、澄清、Schema、JOIN、SQL 安全、空结果和越权。
- 增加故障注入：模型超时、向量库不可用、数据库超时、缓存不可用。
- 建立离线评测门禁和线上质量看板。
- 增加幂等、重试、死信和人工复核状态。

验收：核心 Golden Case 达标后才能发布；所有降级结果明确标注来源和原因。

### Phase 6：Web 体验优化

- 在功能稳定后重做视觉层，不改变后端契约。
- 首页突出驾驶舱、智能问数、商品诊断和自动化中心。
- Agent 页面展示路由、Schema 证据、SQL 校验、工具调用和兜底过程。
- 工作流页面展示步骤、状态、重试、审批和运行记录。

验收：核心演示可在 5 分钟内完整展示，并能解释 Agent 与工作流边界。

## 6. 验收指标

| 指标 | 目标 |
|---|---:|
| 问候/帮助 P95 | < 100 ms |
| 快捷查询 P95 | < 300 ms |
| 驾驶舱 P95 | < 800 ms |
| 明确问数模型调用 | 通常 1 次 |
| SQL 修复调用 | 最多 1 次 |
| 越权表查询拦截率 | 100% |
| 敏感字段脱敏率 | 100% |
| 核心接口 Trace 覆盖 | 100% |
| Golden Case 发布门禁 | 必须通过 |

## 7. 简历表达重点

- 设计 Agent、确定性领域服务和可重试工作流的分层架构。
- 实现低成本路由、Schema 混合召回、关系图补全、NL2SQL 与五层 SQL Guardrail。
- 建设租户/权限隔离、脱敏后缓存、查询超时、降级与全链路追踪。
- 建立电商指标语义层、经营诊断、版本化报告和自动化任务中心。
- 通过 REST/MCP 能力目录为 Web 和企业渠道适配器提供稳定接入边界。
- 设计 Golden Case 和线上指标，评估路由、检索、SQL、Token、延迟与结果质量。
